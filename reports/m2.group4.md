## Milestone Review
### Deliverables
1. Finalization of Bug Fixes from the Milestone 1
2. Recommendations
3. User Interactions
     - Comments
    - Likes
    - Abuse Reports
4. Badge System
5. Search System
6. Testing

### 1: Finalization of Bug Fixes from the Milestone 1
 - Status: Completed
 - In this milestone, we have prioritized to finalize and close the unfinished bugs that were already reported during Milestone 1. After milestone planning the remaining issues regarding bugs are worked and completed.

### 2: Recommendations
 - Status: In Progress
 - In this milestone, we have started to implement a recommendation system, that shall help new-users to adapt to existing communities and all users to find the communities that align with their interests accordingly. Recommendations are not finalized in this milestone, but the roadmap and planning for the recommendation requirements are completed, and the implementation is a work in progress. In the final iteration recommendation system and displaying recommended communities and Home-Page recommendations are going to be implemented, tested and finalized.

### 3: User Interactions ( Comments / Likes / Abuse Reports )
 - Status: Completed
 - We have aimed to improve User Interactions, and add new feature Abuse Reports in this milestone. Some known bugs for comment functionality and likes are fixed. New feature abuse reporting is planned and implemented. Members can now create abuse reports to be reviewed by moderators.

### 4: Badge System
 - Status: Completed
 - In this milestone we have introduced a new feature, badge system. Users can acquire badges through different ways such as likes, posts or being a member to a community for certain amount of time. All the requirements for badge system are implemented and completed, and according to the demo review several new system wide badges will be introduced in the final milestone.

### 5: Search System
 - Status: In Progress
 - We have introduced a basic & advanced search system in this milestone:
   - Basic search that consists of searching through posts, communities, and users.
   - Advanced search that includes using specific fields and templates to refine search results.
 - Within our backlog and requirements this deliverable was marked as completed, but according to the comments & feedback that we have recieved during second demo presentation, we are going to refine and enhance the Search System.

### 6: Testing

1. **Unit Testing:**
   - All major API endpoints have been tested individually, covering a range of scenarios such as valid inputs, edge cases, and error handling. 

2. **Integration Testing:**
   - We have performed integration testing on multiple endpoints to ensure that they interact correctly, such as:
     - **User and Community Integration**
     - **Post and Comment Integration** 
     - **Search Functionality Integration** 

3. **Mock Data:**
   - Mock users, communities, posts, and templates were created within each test to ensure that tests run in isolation and do not depend on actual database data.
   - Mocking of database entries was used for all CRUD operations, user role management, and community interactions.

4. **Error Handling and Edge Cases:**
   - Tests cover edge cases and error scenarios such as invalid user IDs, missing data, or unauthorized actions (e.g., accessing a community the user is not a member of).
   - Tests assert that appropriate error responses are returned (e.g., HTTP 400 or HTTP 404).

6. **Future Work:**
   - More tests will be introduced as we continue implementing new features.
   - Automated Testing will be integrated to CI/CD Pipeline.
   
5. **Coverage Reporting:**
   - A code coverage tool (`pytest-cov`) has been integrated into the testing framework. Coverage reports are generated to highlight which parts of the code are well-covered by tests and which parts need more attention.

### Project Completion

 - Planning for the final iteration & final milestone are done, with some minor changes to the existing planning we've had. These changes include several incomplete issues and comments from second demo & review, that will be discussed in depth within the "Evaluation" chapter.
 
 - For the final iteration we aim to spend considerable amount of time using the app and making changes ( recommendation system tuning, introducing new badges etc. ) according to what a user can ask for. In short, user experience is going to be a priority for our team.

 - Also in this final iteration, we have decided to co-operate for each task more than what we have before. Our team noticed for some tasks, after planning and assignment is done, design and completion of the task is up to one or two members. For this iteration we plan to brainstorm for each task as a group as much as possible. We believe that by doing so, every member of the team will have a more refined, common vision of the final product that we work towards.
 


## Evaluation

 - During the second demo presentation, we have had some day-zero bugs (unexpected dark-light theme changes on certain pages) and some deployment problems that we are aware of, such as API Key for geolocation field's external API calls. We have taken necessary steps and planning to resolve these key points in the final iteration.
 - Additionally, feedbacks regarding user interaction, user engagement and badge system are noted, and discussed on our next meeting on Tuesday after the demonstration. First of all, we plan to improve our badge system by introducing several new badges, and a tier system within badges that require elevated goals for each tier.
 - User engagement and user experience will be our main concern through final iteration, for that we plan to co-operate more for each task to improve our decision making process, and spend more time on Communiche to reveal possible reshapes to existing issues & nice-to-have features.
 - Updates that are mentioned above are going to slightly change our existing issues, but the project plan is going to be mostly the same.
